Windows Update が「ダウンロード中 0%」のまま何時間も動かない、インストールが 99% で止まる、再起動のたびに同じ更新を繰り返す、といった状態は家庭でもよく出ます。画面だけ見ると壊れたように見えますが、多くは **空き容量不足、途中で切れた配布ファイル、サービスが止まっている** のいずれかです。

この記事は Windows 10 / 11 の個人向け PC を対象にします。会社や学校のアカウントで「組織によって管理されています」と出る場合は、最後の節を先に見てください。

## 症状の見分け

- **設定 → Windows Update** のパーセントが、30分以上まったく動かない
- 「ダウンロードしています」と出るが、ネットワーク使用量がほぼゼロ
- 再起動後も同じ更新が並び、エラーコード（`0x80070070`、`0x80070002`、`0x80240034` など）が履歴に残る
- 「作業を完了しています」が数時間続く（大型更新のとき）
- 更新のたびに「ディスク領域が不足しています」と出る

パーセントがゆっくりでも動いていれば、回線が細いだけのことがあります。数時間ゼロのまま、またはエラーコードが付いているときが、この記事の対象です。

## よくある原因

1. C ドライブの空きが足りない（目安として、品質更新でも数GB、大型更新は 10GB 以上空いていないと失敗しやすい）
2. **更新を一時停止**したまま期限が切れ、中途半端なファイルが残っている
3. 従量制課金接続になっていて、更新のダウンロードが抑制されている
4. `SoftwareDistribution` に壊れた配布ファイルが残っている
5. ドライバーやセキュリティソフトが、再起動直後のインストールを止めている
6. ドメインや学校アカウントで、更新のタイミング自体が管理者側の設定になっている

空き容量が怪しいときは、先に [ストレージ不足の片付け](/articles/windows-storage-full/) を進めてから戻ると遠回りが減ります。

## 直す前に

- **更新の履歴**を開き、失敗している更新名とエラーコードをメモする
- 作業中に電源を抜かない。ノートなら充電器をつなぐ
- 「今すぐ再起動」を連打しない。止まっているのがダウンロード段階か、再起動後のインストール段階かを画面で確認する

> **注意:** 「更新修復ツール」「1クリックで Windows を最適化」系の実行ファイルは使わないでください。以下の標準画面と、Microsoft が案内しているフォルダーの入れ直しで足りることがほとんどです。

## 手順

### 1. 空き容量と一時停止を先に見る

1. **設定** → **システム** → **ストレージ** で、C ドライブに **10GB 以上**空いているか見る。足りなければ一時ファイルから消す。
2. **設定** → **Windows Update** を開き、**更新の一時停止**がオンなら解除する。
3. 使っている接続が Wi-Fi なら、**設定 → ネットワークとインターネット → Wi-Fi → 接続中のネットワーク**で **従量制課金接続**がオフか確認する。
4. **更新プログラムのチェック**を押し、数分待ってパーセントが動くか見る。

これで進み始めたら、完了まで放置します。途中で電源を切らないでください。

### 2. トラブルシューティング ツールを一度だけ使う

1. **設定** → **システム** → **トラブルシューティング** → **その他のトラブルシューティング ツール**。
2. **Windows Update** の **実行する**。
3. 案内どおり再起動し、もう一度更新を見る。

同じツールを何度も連続実行しても効果は増えません。1回試してダメなら手順3へ進みます。

### 3. Windows Update 関連サービスを入れ直す

1. `Windows` キーを押し、`services` と入力して **サービス** を開く。
2. **Windows Update**（`wuauserv`）を探し、状態が「実行中」か見る。停止していたら右クリック → **開始**。スタートアップの種類は **手動** または **自動** で構いません。
3. 同様に **Background Intelligent Transfer Service**（BITS）も実行中にする。
4. 設定の Windows Update に戻り、再チェックする。

会社PCで開始できない、またはすぐ止まる場合は、ポリシーで止められていることがあります。個人で無理に自動へ変えないでください。

### 4. 配布フォルダーを作り直す（ダウンロードが壊れているとき）

エラー `0x80070002`、`0x80070003`、`0x80240034` や、毎回同じ KB で失敗するときに有効です。ダウンロードのやり直しになるので、回線の使用量は増えます。

1. `Windows` キーを押し、`cmd` と入力し、**コマンド プロンプト**を **管理者として実行**。
2. 次を1行ずつ実行する。失敗メッセージが出た行はメモし、残りの行は続ける。

```text
net stop wuauserv
net stop bits
net stop cryptSvc
net stop msiserver
```

3. エクスプローラーで `C:\Windows\SoftwareDistribution` を `SoftwareDistribution.old` に名前変更する（中のファイルを手で消さない）。
4. 同じコマンド プロンプトで、止めたサービスを戻す。

```text
net start cryptSvc
net start bits
net start wuauserv
net start msiserver
```

5. PC を再起動し、**Windows Update** からチェックし直す。

名前変更に失敗するときは、手順の `net stop` が通っていないことが多いです。サービス画面で Windows Update が停止していることを確認してから、もう一度リネームします。

### 5. コンポーネントストアを点検する（大型更新や 0x80073712）

1. 管理者のコマンド プロンプトで次を実行し、完了まで待つ（十数分かかることがあります）。

```text
DISM /Online /Cleanup-Image /RestoreHealth
sfc /scannow
```

2. 両方の結果に「修復しました」または「違反を検出しませんでした」と出たら再起動し、更新を再実行する。
3. DISM がソース不足で失敗するときは、その場でネットにつながっているか、VPN を切ってからやり直す。

アプリ自体が開けなくなったあとに更新を急いでいる場合は、先に [実行できませんエラー](/articles/windows-app-cannot-run/) で実行ファイル側を切り分けてください。起動直後に常駐が多すぎて更新画面が固まるように見えるときは [スタートアップの整理](/articles/windows-startup-apps/) も有効です。

## まだ直らないとき

- **作業を完了しています** が 3時間以上、ディスクアクセスもファンも静か → 強制終了は最終手段です。一度だけ長押しで電源を切り、起動後に更新の履歴を見る。途中だった大型更新はロールバック画面に入ることがあります。自動修復やスタートアップ修復に入ったら [起動しないときの手順](/articles/windows-startup-repair/) へ切り替える
- 特定のドライバー更新だけ失敗する → Windows Update からその項目を一時的に「更新を7日間一時停止」し、PCメーカーの公式ドライバーを先に入れる。外付けモニターまで消えたあとの更新失敗は [ディスプレイが映らない手順](/articles/external-display-no-signal/) と同時に起きることがあります
- エラーコードを検索するときは、KB番号とコードをセットで公式ドキュメントを見る。まとめサイトのレジストリ配布は使わない
- 職場・学校アカウント、または設定に **組織によって管理されています** と出る → 個人の手順では終わらないことがあります。IT 担当へ、更新の履歴のスクリーンショットとエラーコードを渡す

## まとめ

更新が止まっても、本体故障より **空き容量、一時停止、壊れた配布ファイル** が多いです。容量を確保してからチェックし直す → トラブルシューティング1回 → サービスの確認 → `SoftwareDistribution` の入れ直し、の順が安全です。再起動中の画面で電源を切るのは、何時間も無反応なときの最後にします。
