タスクバーの時計が数分ずれている。日付が昨日や来年。自動設定をオンにしても戻らない。https が急に証明書エラーになるときも、中身より先に時計です。警告画面そのものは [接続がプライベートではありません](/articles/browser-connection-not-private/) です。

## 症状の見分け

- タスクバーの時刻が、スマホや電波時計より数分〜数時間ずれている
- 日付が 2000年、2012年、来年など、あり得ない値になる
- **時刻を自動的に設定する** がオフのまま。オンにしてもすぐオフに戻る。灰色で触れない
- **今すぐ同期** が失敗する、または「同期しています」のまま終わる
- 海外のタイムゾーン（太平洋標準時など）になっていて、予定が9〜16時間ずれる
- コンセントを抜いて起動すると、毎回古い日付に戻る
- Windows と Linux を同じ PC で切り替えるたびに、片方の時計が狂う

数秒の誤差は、この記事の対象外です。会議や証明書で困るのは、だいたい分単位以上です。

## よくある原因

1. **時刻を自動的に設定する** と **タイムゾーンを自動的に設定する** がオフ。旅行先や手動変更の名残
2. インターネットに出ていないので、時刻サーバーへ届かない
3. Windows Time サービスが止まっている。職場 PC ではポリシーで灰色になることもある
4. タイムゾーンが「(UTC) 協定世界時」や海外のまま
5. Windows と Linux / 古い macOS のデュアルブートで、UTC とローカル時刻の扱いが食い違う
6. マザーボードのボタン電池切れ（電源を完全に落とすと、日付が毎回リセットされる）

## 直す前に

- 手元のスマホの時刻を基準にする。テレビのニュース字幕でもよい
- 出典不明の「時刻修復ツール」や、レジストリ配布は使わない
- 職場や学校の PC でスイッチが灰色なら、個人では終わりません。IT 担当へ渡す

> **注意:** BIOS 画面で時計を合わせる必要は、この記事ではありません。Windows 側が合えば、日常のアプリとブラウザは足ります。マザーボード電池の交換は分解を伴うので、保証期間内ならメーカーまたは修理店へ。

## 手順

### 1. 自動設定をオンにして、今すぐ同期する

1. **設定** → **時刻と言語** → **日付と時刻**。
2. **時刻を自動的に設定する** をオン。 **タイムゾーンを自動的に設定する** もオン。
3. **タイムゾーン** が **(UTC+09:00) 大阪、札幌、東京** か見る。海外の名前なら、いったん自動をオフにして東京を選び、またオンに戻す。
4. **追加の設定**（画面によっては **関連設定**）の **日付と時刻を同期する** で **今すぐ同期** を押す。成功すると、最終同期の日時が更新されます。
5. タスクバーの時計が、スマホと1分以内で揃うか見る。ブラウザを開き直して、さっき失敗していた https を試す。

オンなのに年が違うときは、いったんオフ → 正しい日付を手で入れる → またオン、です。手入力のまま放置すると、またずれます。

同期が失敗するときは、先にネットへ出られるか見てください。Wi-Fi はつながっているのにサイトが開けないなら [インターネットなしの切り分け](/articles/wifi-connected-no-internet/) が先です。

### 2. 地域と、夏時間の取り違えを外す

日本に居るのに時刻だけ9時間ずれるときは、タイムゾーンが UTC のまま、というパターンが多いです。

1. 同じ **日付と時刻** 画面で、**タイムゾーン** を東京にする。
2. **地域**（**時刻と言語 → 言語と地域**）の国または地域が **日本** か見る。
3. 海外旅行から帰ったあとは、自動タイムゾーンがオフのままだと現地時刻のまま残ります。オンに戻す。
4. 夏時間のある国のゾーンを選んでいると、日本に居ても1時間ずれます。東京以外を使う用事が終わったら戻してください。

カレンダーの予定だけずれるアプリは、Windows の時計ではなく、そのアプリのタイムゾーン設定です。タスクバーが合っているなら、OS 側はここまでで足ります。

### 3. Windows Time サービスを起こす

自動スイッチがすぐ戻る、同期ボタンが灰色、のときだけ見ます。

1. `Win` キーを押し、`services.msc` と入れて **サービス** を開く。
2. **Windows Time** を探してダブルクリック。表示名が英語のままなら Windows Time です。
3. **スタートアップの種類** を **手動** または **自動** にする。 **停止** なら **開始** を押す。
4. サービスの画面を閉じ、手順1の **今すぐ同期** をもう一度試す。

職場 PC でこの項目が灰色なら、ドメインの時刻サーバーを見ています。個人の「今すぐ同期」では上書きできません。IT 担当へ、画面のスクリーンショットを渡してください。

コマンド プロンプトを使う場合は、管理者で `w32tm /resync` です。失敗メッセージに「サービスが起動していません」と出たら、上のサービス画面が先です。レジストリはいじりません。

### 4. デュアルブートと、電源を落とすと戻る場合

同じ SSD で Windows と Ubuntu などを切り替えていると、起動のたびに片方だけ数時間ずれます。Linux 側が UTC、Windows 側が日本時間、という食い違いです。

1. 常用するほうの OS で、時計を自動同期にする。
2. もう一方の OS でも、配布元の案内どおり **ローカル時刻** に揃える。Windows のレジストリで UTC に変える手順は、この記事では使いません。
3. 切り替え後にまたずれたら、Windows で手順1の同期だけやり直す。証明書エラーが出ていれば、同期のあとにブラウザを開き直す。

コンセントを抜く、ノートのバッテリーを外す、長いあいだ電源オフ、のあと **毎回** 2000年や 2012年に戻るなら、マザーボードのボタン電池切れです。Windows の同期は一時的に直しますが、電源を落とすたびに戻ります。自分で蓋を開けないなら、手順を試した記録（抜く前は合う、抜くと戻る）を添えて修理へ出してください。BIOS の更新は不要です。

### 5. まだ同期に失敗するとき

1. セキュリティソフトの「時刻保護」や VPN を、切り分けのあいだ切る。切ると同期できるなら、そのソフトの除外を公式案内で入れる。止めっぱなしにはしない。
2. 会社 VPN を切った状態で **今すぐ同期** を試す。つなぐと失敗するなら、VPN 側です。
3. 別の DNS に変えていると、時刻サーバー名だけ解決できないことがあります。[DNS の手順](/articles/windows-dns-server-problem/) で番号通信を確認してから、もう一度同期する。
4. 高速スタートアップのあとだけ古い時刻になるノートは、**設定 → システム → 電源** 付近の高速スタートアップを切り分けでオフにし、完全シャットダウンして入れる。

仮想マシン（Hyper-V や VirtualBox）のゲストは、ホスト側の時計をコピーします。ゲストだけずらしても、再起動で戻ることがあります。ホスト側を先に合わせてください。

## まだ直らないとき

- `ERR_CERT_DATE_INVALID` が残る → 手順1のあとブラウザを完全終了。まだなら [証明書の手順](/articles/browser-connection-not-private/)
- 同期は成功と出るが、見た目が9時間ずれ → 手順2のタイムゾーン。東京以外が残っていないか見る
- 自動が灰色 → 手順3。職場なら担当へ
- 電源オフのたびに 2000年代へ戻る → ボタン電池。分解が不安なら修理店
- 時刻合わせのあと、特定アプリだけ予定がずれる → そのアプリのタイムゾーン。Windows の時計は触らない

## まとめ

東京のタイムゾーンで自動同期が通れば、ほとんどのずれはここで終わります。電源を落とすたびに戻るときだけ、ボタン電池です。
