# 記事の追加ガイド（量産用）

手順ナビの本文は Markdown（または MDX）です。新しい記事は **テンプレートをコピーして frontmatter を埋める**だけでビルド対象になります。広告枠はレイアウト側に固定してあるので、本文に広告コードを書かないでください。

## 最短手順

1. `src/content/articles/_template.md` をコピーする。
2. ファイル名を **英数字とハイフンのスラッグ** にする（例: `windows-taskbar-missing.md`）。
3. frontmatter を実データに書き換える。`draft: false` にするまで本番に出ない。
4. 本文を「症状 → 原因 → 事前確認 → 手順 → まだ直らないとき → まとめ」で書く。
5. 関連する既存記事へ内部リンクを 1〜2 本入れる。
6. ローカルで `npm run dev` し、`/articles/<スラッグ>/` を開いて見出し・日付・カテゴリを確認する。
7. `npm run build` が通ることを確認してからコミットする。

公開 URL は `https://<ドメイン>/articles/<ファイル名から拡張子を除いたもの>/` です。

## Frontmatter

| フィールド | 必須 | 内容 |
|---|---|---|
| `title` | はい | 検索されそうな言い方。エラー文は「」で囲む。 |
| `description` | はい | おおよそ 80〜140 字。対象OSと症状を含める。 |
| `category` | はい | 次のいずれかだけ: `windows` `smartphone` `network` `peripherals` |
| `tags` | はい（空配列可） | 機種名・エラー名・手段。本文に無い語を増やしすぎない。 |
| `updated` | はい | `YYYY-MM-DD`。内容を直したら必ず更新する。 |
| `draft` | はい | `true` のあいだは一覧・サイトマップ・記事URLに出ない。 |

日付はビルド時に Date へ変換されます。時刻は不要です。

## ファイル名（スラッグ）

- 使う文字: `a-z` `0-9` `-` のみ。
- OSや製品名を先頭に置くとカテゴリ内で並びが読みやすいです。  
  良い例: `android-wifi-cannot-connect.md`  
  弱い例: `howto1.md` / `完全攻略！！.md`
- 先頭が `_` のファイルはコレクションから除外します（テンプレート用）。

## 本文の型

量産しても薄いページにしないための最低限です。

1. **導入**（誰の・何の不具合か、この記事の範囲）
2. **症状の見分け**（読者が「自分のことだ」と判断できる）
3. **よくある原因**（断定しすぎない。番号付き）
4. **直す前に**（バックアップ、公式以外の実行ファイルを使わない、など）
5. **手順**（画面名 → 操作 → 成功したときに見える状態）
6. **まだ直らないとき**（次の切り分け、サポートへ渡す情報）
7. **まとめ**（覚えて帰る1段落）

警告は Markdown の引用（`>`）にします。スタイル側で注意枠になります。

```markdown
> **注意:** ネットワーク設定のリセットは Wi-Fi パスワードも消します。
```

内部リンクはサイト内パスを使います。

```markdown
回線が先に怪しいときは [DNSサーバーに問題があります](/articles/windows-dns-server-problem/) を見てください。
```

## 書いてはいけないこと

- キーワードを並べただけの導入、同じ手順のコピペ量産（ドアウェイ）
- 「必ず直る」「100%」などの保証
- 出典不明のレジストリファイル、出所不明の「修復ツール」への誘導
- アダルト・違法改造・ライセンス回避
- 本文中への広告ネットワークタグ（AdSense 等）。枠は `AdSlot` コンポーネントが記事レイアウトに既にある

## 広告枠

`src/layouts/ArticleLayout.astro` が次を自動挿入します。

- `top` … タイトル直下
- `mid` … 本文の直後（関連記事の前）
- `bottom` … 関連記事の後

プレースホルダは `src/components/AdSlot.astro` です。head の AdSense スクリプトは既定のクライアント ID で入ります。記事の `ins` ユニットは枠ごとのスロット ID があるときだけ出します。記事本文に広告コードを書かないでください。量産記事側で枠を増減する必要はありません。

## カテゴリの追加

新しい大分類が必要になったときだけ:

1. `src/lib/categories.ts` の `categoryIds` と `categories` を増やす。
2. 既存記事の `category` を必要なら付け替える。
3. `npm run build` でスキーマ検証が通ることを確認する。

カテゴリページは `src/pages/categories/[category].astro` が自動生成します。

## MDX を使うとき

コンポーネントを本文に埋めたい場合は拡張子を `.mdx` にします。frontmatter の規則は同じです。まずは Markdown のままで問題ありません。

Amazon の関連リンクが手順の切り分けに自然なときだけ、本文に `AffiliateProduct` を1つ置いてください（押し売りにしない）。`search` に amazon.co.jp の検索語を渡します。未確認の ASIN は書かないでください。

```mdx
<AffiliateProduct
  title="HDMIケーブル"
  why="入力切替のあとにケーブル不良を疑う段階なら。"
  search="HDMIケーブル 2.0"
  cta="Amazon.co.jpでHDMIケーブルを探す"
/>
```

コンポーネントは `ArticleLayout` から MDX に渡します。タグは `PUBLIC_AMAZON_ASSOCIATE_TAG`（未設定時は `wasshoi22451-22`）です。
